# OgeNotes — Product and Engineering Roadmap

## Milestone #105 — Working Notes search across GitHub pages + keyboard Save (18 Nov 2026)

**Product milestone, not a security or attestation milestone.**

- **Fixed misleading search:** The GitHub Notes editor initially loads 20 committed Notes; existing search filters only loaded Notes. When searching while other pages exist, the UI now says **No matches in loaded notes yet** instead of claiming a missing Note, and offers **Search remaining GitHub Notes** to continue fetching and searching the user's own GitHub Notes.
- **Progressive, on-demand search:** Adds a small browser-only `loadVaultSearchPages` helper, using the existing `/api/vault/notes-main?paged=true&limit=25&cursor=...` endpoint. A click loads up to 12 additional pages / 300 Notes, deduplicates records, and shows the loaded count. Click again to scan more large Vaults; no new provider API, indexed MongoDB Note content, new credential, or always-on background search.
- **Pause and resume:** A **Stop search** action aborts pending reads, preserves already accepted pages and the last confirmed cursor, and allows the user to resume. A Notes refresh/Save aborts ongoing searches before refreshing its GitHub snapshot. Invalid or stale pages show a recoverable error rather than pretending search is complete.
- **Typing ergonomics:** Adds `Ctrl+Enter` / `⌘+Enter` Save from the modal or fullscreen editor via the existing native form `requestSubmit()`; all current Save/draft/revision/error handling stays in place.
- **Tests:** New M105 pagination helper tests cover finding a result beyond page one, 900-note bounded/resumed scans, Stop before/after a response, invalid cursors/pages, UI integration and keyboard Save. Existing pagination, Notes adapter, MongoDB and desktop/mobile tests remain in CI.
- **Readiness:** This is implemented on the existing draft feature branch; independent live account testing is still needed to confirm the actual GitHub and browser user journey. No change to GitHub Notes storage choice, no merge, no production deployment. Track by actual flows, **not the retired ~96% estimate**.
- **Next:** #106 — real editor UX polish (clear Save feedback, full-screen/mobile behavior, efficient note access across larger libraries), then Quick Notes/AirNotes/extension convergence.

## Oge Vault milestone #103 — F7: fix real manual-check request and same-Note relink gaps (18 Nov 2026)

- **Implemented, tested locally in CI (status separately verified on final head):** Hardened the M100 owner-clicked `GET mode=verify` private GitHub Note check. Requires `X-Oge-Verify-Intent: manual` custom header and matching staging request origin. If `Origin` or `Sec-Fetch-Site` is present, its value must match same-origin. A cross-site navigational GET carrying SameSite=Lax signed cookies now fails with 403 before GitHub token creation or verification rate-limit consumption. The Learning Tracks UI and protected Playwright operator CLI explicitly send this header. New pure `manualLearningTrackNoteCheckAllowed` helper has direct Request-based positive and negative tests.
- **Same-Note unlink/relink detection:** Public owner-scoped Note-link metadata now includes a random per-link `linkId` from its MongoDB record UUID (not a GitHub write token). M101 and M102 snapshot checks now compare **both** `noteId` and `linkId`, blocking a stale observation when another device unlinks and relinks the same Note ID. Link IDs never enter redacted reports. Individual M100 checks already re-read record `_id` and keep point-in-time caveats. New negative tests cover same-Note relinks at initial and final session reads.
- **Operator URL safety:** M101 now requires an explicitly named `staging` or `preview` HTTPS hostname, consistent with M102 and existing Vault staging guardrails, rather than any HTTPS origin. This reduces accidental acceptance against production-looking hosts. No new OAuth login, provider writes, restore, quarantine release, automatic retry or deployment.
- **Known limits:** Same-origin custom-header intent is not an OAuth credential or proof of human presence; a compromised same-origin script can still request checks. Random link revisions detect changes visible between checks but cannot make MongoDB, GitHub and the browser atomic. Any check result can become stale immediately afterward.
- **External acceptance:** Real disposable OAuth issuer and physical-device evidence, 403/429/5xx GitHub provider behavior and independent security review remain **UNEXECUTED**, operator-dependent, mandatory release HOLD. Prototype completion still **~96% historical rough estimate**; production readiness BLOCKED and **not quantified**, PR #35 draft and unmerged.

### Storage and UI contract

- **GitHub (mandatory private, user-owned vault)** is authoritative for *committed* Notes, Quick Notes, AirNotes, revision history, future Learning Tracks notes, extension/imports/restores. Only a confirmed GitHub write may show **Saved**; GitHub remains the source of truth during reconciliation.

- **MongoDB `vault_files`** is an optional metadata index of opaque note ID, subject ID, GitHub file path, repository ID, SHA and sync status. 5. No secrets in Git: use local environment files that are ignored by Git and deployment secret stores.
6. Update this roadmap when scope changes; record the reason and acceptance impact.
7. Do not claim a feature or security gate is complete until it has been implemented and verified.
